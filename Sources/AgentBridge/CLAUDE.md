# CLAUDE.md — Sources/AgentBridge

This target contains the OpenAI GPT-Live call session. It depends on `HFPCore`, `AudioPipeline`, and `Shared` and has no external package dependencies.

`RealtimeCallSession.swift` defines `CallSession`, which opens a server-side WebSocket using `OPENAI_API_KEY` and starts the fixed model `gpt-live-1`. It uses Responses delegation with `gpt-6.1-sol` for appointment reasoning and tool selection. `prepare()` is called while an outgoing HFP call is dialing. `startAudio(using:)` is called only after the phone reports an active call. The session accepts and emits mono PCM16 at 24 kHz.

`CallConfiguration.swift` defines the input JSON (`name`, `dateOfBirth`, `insurance`, `additionalDetails`, optional `gender`, and optional `language`) and the persisted appointment-result schema. The exact decoded caller JSON is supplied both as a completed developer message in the Live session's initial `input` and in the Responses backend instructions. The Live context marks those values as trusted, verbatim facts that remain quiet unless relevant or requested. PhoneBT maps `male` to the `cedar` Live voice and `female` (or an omitted value) to `marin`; this is an application convention because OpenAI names voices without official gender labels. `language` is injected into the session instructions and defaults to English; it is not an audio-output API parameter. The saved result contains `status` and optional appointment date (`MM-DD`, without a year), appointment time, practice, and notes. Notes intentionally repeat the confirmed appointment details as a useful human-readable summary rather than relying only on the structured fields.

The Live instructions own conversational style, language, backchannels, interruption handling, silence, and delegation policy. Detailed appointment, IVR, and result rules live in the Responses backend instructions. For automated phone menus, the backend may call `send_dtmf` with one validated tone (`0`–`9`, `*`, or `#`) at a time; `AgentBridge` forwards it as an out-of-band HFP command through `HFPDevice.sendDTMF(_:)`, not through the PCM audio stream, and returns the outcome with `response.item.create` before continuing the backend response. After GPT-Live finishes its own final goodbye, it delegates the final outcome and call closure immediately without waiting for another callee response. The backend then supplies the structured outcome to `end_call`. Local playback must settle before HFP hangup because GPT-Live has no per-utterance audio-done event; a bounded fallback prevents a lost `AVAudioPlayerNode` completion callback from blocking hangup indefinitely. Result persistence occurs when the HFP call actually closes; an unstructured termination produces an `unknown` result.

Keep GPT-Live protocol and delegation handling here. Keep audio conversion in `AudioPipeline` and HFP state/commands in `HFPCore`.
