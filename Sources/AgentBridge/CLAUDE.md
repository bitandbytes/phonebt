# CLAUDE.md — Sources/AgentBridge

This target contains the OpenAI GPT-Live call session. It depends on `HFPCore`, `AudioPipeline`, and `Shared` and has no external package dependencies.

`RealtimeCallSession.swift` defines `CallSession`, which opens a server-side WebSocket using `OPENAI_API_KEY` and starts the fixed model `gpt-live-1`. It uses Responses delegation with `gpt-6.1-sol` for appointment reasoning and tool selection. Both `prepare()` and `startAudio(using:)` are called only after the phone reports an active call, avoiding Live-session expiry during long ringing. The session accepts and emits mono PCM16 at 24 kHz. A five-second rolling PCM buffer preserves initial callee audio while startup completes. Unexpected closure while HFP remains active triggers up to three replacement-session attempts; retained transcript history is supplied at startup so the replacement can continue the conversation without printing transcript text.

`CallConfiguration.swift` defines the input JSON (`name`, `dateOfBirth`, `insurance`, `additionalDetails`, optional `gender`, optional `language`, optional `telephoneNumber`, and optional string-valued `doctorReferralDetails`) and the persisted appointment-result schema. The exact decoded caller JSON is supplied once as a completed developer message in the Live session's initial `input`; Responses delegation receives that conversation context. The Live context marks those values as trusted, verbatim facts that remain quiet unless relevant or requested. Referral keys and values may contain German medical terminology and identifiers; preserve them verbatim. PhoneBT maps `male` to the `cedar` Live voice and `female` (or an omitted value) to `marin`; this is an application convention because OpenAI names voices without official gender labels. `language` is injected into the session instructions and defaults to English; it is not an audio-output API parameter. The saved result contains `status` and optional appointment date (`MM-DD`, without a year), appointment time, practice, and notes. Notes intentionally repeat the confirmed appointment details as a useful human-readable summary rather than relying only on the structured fields.

The Live instructions own conversational style, language, backchannels, interruption handling, silence, and delegation policy. Detailed appointment, IVR, audio-gain, and result rules live in the Responses backend instructions. For automated phone menus, the backend may call `send_dtmf` with one validated tone (`0`–`9`, `*`, or `#`) at a time; `AgentBridge` forwards it as an out-of-band HFP command through `HFPDevice.sendDTMF(_:)`, not through the PCM audio stream, and returns the outcome with `response.item.create` before continuing the backend response. When GPT-Live detects consistently quiet incoming speech, the backend may call `set_input_volume` with an absolute 1–29 dB hardware gain; the active `RealtimeAudioBridge` applies it through `AudioSessionManager` and reports unsupported controls or invalid values. The backend calls `record_appointment_outcome` as soon as confirmed outcome details exist and again if they change; this checkpoints result data independently of who ends the telephone call. `end_call` is accepted only after a checkpoint exists. If HFP reports call end before any checkpoint, `CallSession` keeps the Live connection open for up to five seconds and asks the backend to recover the best structured outcome from conversation context before persisting a fallback. Local playback must settle before model-requested HFP hangup because GPT-Live has no per-utterance audio-done event; a bounded fallback prevents a lost `AVAudioPlayerNode` completion callback from blocking hangup indefinitely.

Keep GPT-Live protocol and delegation handling here. Keep audio conversion in `AudioPipeline` and HFP state/commands in `HFPCore`.

Raw GPT-Live input and output PCM dumps are always enabled and are written beside the input configuration and appointment-result files. Audio-dump creation is best-effort and logs an error without aborting the telephone call when the directory is not writable.

Terminal diagnostics include event-driven call activity without transcript text: waiting for the callee, callee speaking, assistant speaking, waiting for or running the delegated backend, ongoing discussion, result recovery, and closure. Repeated transcript/audio fragments are coalesced into state changes, and a 60-second heartbeat repeats the current state and elapsed active time. Do not print transcript content by default because it may contain medical and personal information.
